无重复字符的最长子串

滑动窗口 + 字典。左指针只在必要时「跳」到冲突字符之后，绝不用一格一格挪回去 —— 这一个差别， 就是 O(n) 与 O(n²) 的分界线。

      最容易写错的一行：if ch in last and last[ch] >= start。
      第四步里 'a' 上次出现在下标 0，但那时 start 已经跳到 2，位置 0 早已被滑出窗口。
      若此时还执行 start = last['a'] + 1，左端就会倒退，窗口变成 "aba"，
      把早已淘汰的重复字符又请回来，答案会错成 3。
    

  


  
  

    

      
复杂度对比：为什么「只回退一格」会超时

      
同一个最坏用例，两种写法并行跑一遍。注意看第一行指针的回退。

    


    

      

        最坏用例：
        

          
          
          
        

      


      

        

          重启版
          左端只回退一格 → O(n²)
          已扫描 0 次
        

        

          
          

        

        

      


      

        

          字典版
          左端直接跳到冲突字符之后 → O(n)
          已扫描 0 次
        

        

          
          

        

        

      


      

    


    

      为什么会这样：重启版一旦发现重复，就把左端挪一格再把整段重扫一遍，于是同一段前缀被反复确认；
      字典版则把左端直接送到冲突字符的下一个位置，同一段前缀永远只扫一次。
      串长 n 时，重启版的内层循环会执行约 n(n+1)/2 次，字典版恒为 n 次。
